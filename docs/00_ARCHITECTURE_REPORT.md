### 1.2 Ключевые архитектурные решения

**Продуктовые:**
1. **Сервис, а не каталог** — фокус на доверие и процесс, а не на количество лотов
2. **Проверка автомобиля** — центральный элемент доверия
3. **Доверие ДО заявки** — доказательства, затем CTA
4. **Виталий как эксперт** — баланс персонализации и корпоративности
5. **Отслеживание заказа** — обязательная функция MVP

**Технические:**
1. **Модульный монолит** — Next.js с API Routes (не микросервисы)
2. **PostgreSQL + Prisma** — типобезопасность end-to-end
3. **UUID для всех ID** — безопасность через сложность
4. **Централизованный финансовый движок** — консистентность расчётов
5. **Обезличивание Telegram** — строгое соблюдение 152-ФЗ
6. **Tracking token** — уникальная ссылка вместо публичного поиска
7. **Mobile-first** — проектирование сначала для мобильных

**Дизайн:**
1. **Чёрный/красный/белый** — автомобильная эстетика + digital-сервис
2. **Не копировать automotive-стандарт** — самостоятельный визуальный язык
3. **Tailwind CSS + Radix UI** — быстрая разработка + accessibility

## 2. Какие вопросы остались

### 2.1 Критические (блокируют запуск)

1. **КВ-001: Контактные данные** — телефон, email, Telegram-канал, режим работы
2. **КВ-002: Реальный контент** — фото Виталия, офиса, команды, автомобилей
3. **КВ-003: Биография Виталия** — должность, обращение, опыт
4. **КВ-004: Данные команды** — имена, должности, фотографии

**Временное решение:** Использовать placeholders, заменить перед production.

### 2.2 Важные (влияют на функционал)

1. **ВВ-001: Публичность цен** — показывать ли цены автомобилей публично?
2. **ВВ-002: Главный CTA** — "Подобрать автомобиль" или другой?
3. **ВВ-003: Сроки доставки** — конкретные сроки из Японии/Кореи/Китая
4. **ВВ-004: Детализация финансов** — показывать ли breakdown расходов клиенту?
5. **ВВ-005: Формат отзывов** — текст + фото или полные истории?

**Временное решение:** Архитектура поддерживает гибкость, решения принять до реализации соответствующих фаз.

### 2.3 Второстепенные (не блокируют)

- Логотип компании
- Социальные сети (кроме Telegram)
- SEO-страницы марок/моделей
- Favicon и Open Graph изображения

**Решение:** Можно добавить позже, не блокируют MVP.

### 2.4 Технические

- Telegram Bot Token (создать перед Phase 10)

## 6. Безопасность и 152-ФЗ

### Реализовано в архитектуре:

✅ **Минимизация данных** — собирать только необходимое  
✅ **Обезличивание Telegram** — строгий запрет на передачу ПДн  
✅ **UUID для tracking** — защита от перебора  
✅ **HTTPS везде** — обязательно  
✅ **Bcrypt для паролей** — cost factor 10  
✅ **JWT для auth** — Access token 1 час  
✅ **Rate limiting** — защита от спама и DDoS  
✅ **Логирование доступа к ПДн** — требование 152-ФЗ  
✅ **Резервное копирование** — ежедневно, хранение 7+ дней

### Требуется перед production:

⚠️ Политика конфиденциальности (юрист)  
⚠️ Проверка соответствия 152-ФЗ (юрист)  
⚠️ Тестирование восстановления из бэкапа
